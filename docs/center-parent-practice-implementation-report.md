## Добавлено

- В `/family` есть отдельные «Ежедневные упражнения» и существующие «Задания специалиста». Без назначения специалиста родитель проходит 16 вопросов и занимается самостоятельно.
- Использованы существующие анкета, адаптивный алгоритм, упражнения, прогресс и родительские таблицы. Повторная регистрация через email и повторное создание ребёнка не нужны.
- Состояние загружается только для серверно связанного ребёнка. Сохранение, локальное хранилище и открытый экран привязаны к владельцу страницы. Смена аккаунта или выход блокируют старую страницу; отложенный результат не записывается другому пользователю.
- Профессиональные оценки и ответы на домашние задания не перезаписываются. Начальная и повторная родительские оценки имеют отдельные типы, ответы и даты.
- Каталог берётся с сервера без скрытого возврата к встроенному набору, с проверкой активности и возрастных границ. Если сохранённый незавершённый план больше нельзя выполнить, показывается понятное ограничение.
- Ошибку сохранения можно повторить. Конфликт с другим устройством не перезаписывает серверные результаты; локальный черновик сохраняется, а явный переход к серверной версии оставляет его локальную резервную копию.
- Для специалиста подготовлена отдельная сводка самостоятельной активности закреплённого ребёнка.

## Почему потребовалась дополнительная схема

Независимая проверка выявила, что обычные отдельные REST-записи не защищают от перезаписи между устройствами. Поэтому подготовлен добавочный SQL с атомарными функциями загрузки/сохранения по версии данных и ограниченной сводкой для специалиста. Он использует существующие таблицы, проверяет владельца/назначение и не создаёт новые аккаунты или детей.

Файл: `supabase/proposed/center_parent_practice_summary.sql`. Это **предложенная миграция, не применённая к базе**. Перед выпуском требуется создать файл миграции штатной командой установленного Supabase CLI, применить SQL и выполнить проверку ролей.

## Принятые решения и ограничения

- Реализация выполнена в существующем изолированном рабочем каталоге, в ветке `agent/center-parent-practice`; краткий журнал ведётся обычными файловыми правками вместо shell-генератора промежуточных файлов.
- Сохранение родителей центра вынесено в небольшой проверяемый модуль. Старый механизм email-родителей не переписывался; добавлена общая защита владельца страницы.
- Использованы фактические маршруты `/plan-ready` и `/recheck/1..8`, а не предположительное название повторной оценки.
- Незавершённые ответы анкеты — локальный черновик конкретного аккаунта и ребёнка. Завершённая оценка, планы и результаты предназначены для синхронизации через новую атомарную функцию. Перенос незавершённой анкеты между устройствами не добавлен.
- Миграция обязательна перед выпуском: без новых RPC новая ветка покажет ошибку загрузки, а не откроет устаревшие данные. Рабочий production остаётся прежним до отдельного разрешения на публикацию.
- Клиническая пригодность существующего банка упражнений и профессиональная редактура переводов отдельно не оценивались. Новых лечебных обещаний или диагнозов не добавлялось.

## Статус публикации

Только локальная реализация и локальные коммиты. Push, объединение с `main`, применение миграции и production-деплой не выполнялись. Посещаемость, платежи, роли и пароли не менялись. Независимая проверка проведена; найденные существенные ошибки исправлены с регрессионными тестами.
